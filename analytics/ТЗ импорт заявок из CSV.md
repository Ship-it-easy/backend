# Техническое задание на импорт заявок из CSV

Версия: 1.1
Дата: 26 сентября 2026 года
Статус: согласовано к разработке

Связанные документы:

- «ТЗ администрирование проектов и кабинеты пользователей»;
- «ТЗ динамическое добавление заявок и публикация многодневного плана»;
- «ТЗ динамический пересчёт при отмене заявки и недоступности инженера»;
- «ТЗ интерфейс экрана Планирование».

## 1. Назначение и принятые решения

Документ определяет импорт новых заявок из CSV в выбранный проект. Источник содержит дату и время начала окна, дату и время окончания окна, адрес и название типа работ. Система сначала проверяет весь файл, показывает ошибки и предупреждения на экране, а затем по явному действию пользователя создаёт все заявки одной транзакцией.

Главные решения:

1. Для заявок принимается только CSV. Файлы XLSX и Numbers не загружаются. Импорт инженеров через XLSX остаётся без изменений.
2. Каждая корректная информационная строка создаёт одну новую заявку. Обновление существующих заявок через импорт не выполняется.
3. Поля берутся из колонок `Тип заявки ВК`, `Начало`, `Окончание` и `Адрес`. Остальные колонки игнорируются.
4. Дата из `Начало` и дата из `Окончание` одной строки должны совпадать. Это значение становится `sla_date`. Разные строки одного файла могут иметь разные даты.
5. Время из `Начало` становится `time_window_start`, время из `Окончание` становится `time_window_end`.
6. При любой ошибке ни одна заявка из пакета не создаётся. Отдельный файл с ошибками не формируется: все ошибки показываются в интерфейсе.
7. После успешного применения пакета создаётся одно событие динамического пересчёта для всех новых заявок проекта.
8. Импортированная заявка получает `status = NEW`, внутренний ID и длительность из типа работ. Приоритет берётся из выбранного типа работ.

Это отдельное ТЗ. Оно заменяет правила прежнего импорта заявок из XLSX в части формата входного файла, названий колонок, проверки адреса, интерфейса ошибок, фоновой обработки и запуска динамического пересчёта. Импорт инженеров и уже сохранённые старые пакеты не изменяются.

## 2. Цели и критерии результата

### 2.1. Цели

- загрузить до 1000 заявок без ручного переноса полей;
- исключить частично применённые и противоречивые пакеты;
- сопоставить типы работ только с действующим справочником проекта;
- сохранить единый российский формат адресов и координаты для маршрутизации;
- предотвратить случайный повтор идентичного импорта;
- передать созданные заявки в действующий механизм динамического планирования одной пачкой;
- дать диспетчеру понятный результат без выгрузки дополнительного отчёта.

### 2.2. Критерии успеха

Функция считается готовой, если владелец или диспетчер может загрузить CSV, покинуть страницу во время проверки, увидеть результат в истории, исправить файл при ошибках либо подтвердить предупреждения и создать все корректные заявки одной операцией. Созданные заявки видны в списке проекта и учтены одним событием динамического пересчёта.

## 3. Границы задачи

### 3.1. Входит в задачу

- CSV-импорт заявок;
- автоматическое определение кодировки и разделителя из согласованного набора;
- фоновая проверка файла;
- проверка структуры и каждой строки;
- сопоставление типа работ;
- нормализация и геокодирование адреса;
- проверка дублей внутри файла, повторного файла и возможных дублей в базе;
- двухэтапный сценарий «проверить» и «создать заявки»;
- экран ошибок и предупреждений;
- история импортов;
- атомарное создание заявок;
- аудит и хранение исходного CSV в течение 30 дней;
- единое событие динамического пересчёта после успешного применения.

### 3.2. Не входит в задачу

- импорт заявок из XLSX или Numbers;
- импорт инженеров из CSV;
- ручное сопоставление колонок;
- создание типов работ из файла;
- обновление, отмена или удаление существующих заявок;
- частичное применение корректных строк;
- редактирование строк CSV внутри интерфейса;
- скачивание отдельного отчёта об ошибках;
- ручное назначение инженера при импорте;
- изменение алгоритмов solver и динамического пересчёта.

## 4. Термины и инварианты

| Термин | Значение |
| --- | --- |
| Пакет импорта | Один загруженный CSV и все результаты его проверки и применения в одном проекте |
| Информационная строка | Непустая строка после строки заголовков, из которой должна быть создана заявка |
| Ошибка | Нарушение, блокирующее применение всего пакета |
| Предупреждение | Возможный дубль существующей заявки; не блокирует применение после подтверждения |
| Нормализованный адрес | Однозначно найденный российский адрес до дома в формате адресного сервиса |
| Контрольная сумма | SHA-256 исходных байтов файла, используемая для обнаружения повторной загрузки |
| Применение | Атомарное создание всех заявок проверенного пакета |

Инварианты:

- пакет относится ровно к одному проекту;
- одна строка создаёт не более одной заявки;
- созданная импортом заявка всегда получает серверный внутренний ID;
- значение колонки `Заявка` и другие внешние номера не сохраняются;
- ошибка любой строки запрещает применение всего пакета;
- отсутствие строки в файле не изменяет и не удаляет существующие данные;
- один пакет можно успешно применить только один раз;
- применение и создание события планирования не могут расходиться: событие записывается в той же транзакции через transactional outbox;
- отображаемые значения и ошибки из одного проекта недоступны пользователям другого проекта.

## 5. Права и проектная изоляция

### 5.1. Разрешённые роли

- диспетчер загружает данные только в собственный проект;
- владелец может выполнить импорт после явного выбора проекта в административном контексте;
- инженер не видит раздел, пакеты и API импорта.

Сервер проверяет роль, проект и состояние проекта для каждого запроса. Скрытие элемента интерфейса не считается проверкой доступа. В заблокированный проект нельзя загрузить, проверить или применить пакет.

### 5.2. Изоляция

Типы работ, поиск возможных дублей, создаваемые заявки, история и события планирования ограничиваются `project_id` выбранного проекта. Переданный клиентом идентификатор другого проекта не даёт доступ к данным и возвращает `404` либо `403` по общему правилу приложения.

## 6. Контракт входного CSV

### 6.1. Формат файла

- расширение: `.csv`;
- максимальный размер: 10 МБ;
- максимум: 1000 информационных строк;
- первая непустая строка является строкой заголовков;
- поддерживаются окончания строк LF и CRLF;
- поддерживаются кодировки UTF-8, UTF-8 с BOM и Windows-1251;
- поддерживаются разделители `;` и `,`;
- кодировка и разделитель определяются сервером;
- значения с разделителем, переводом строки или кавычкой должны быть экранированы по правилам CSV;
- полностью пустые строки игнорируются независимо от положения;
- строка, в которой заполнена только часть обязательных значений, является информационной и проверяется как ошибочная.

Если кодировка или разделитель не определены однозначно, файл получает ошибку уровня пакета. Сервер не пытается разбирать CSV простым разделением строки и обязан использовать полноценный CSV-парсер.

### 6.2. Заголовки

Обязательные заголовки:

| Заголовок CSV | Назначение |
| --- | --- |
| `Тип заявки ВК` | Поиск типа работ текущего проекта |
| `Начало` | Крайний срок и начало временного окна |
| `Окончание` | Контроль крайнего срока и конец временного окна |
| `Адрес` | Поиск и сохранение полного адреса |

Порядок колонок произвольный. Перед сравнением с заголовка удаляются крайние пробелы и BOM. Регистр и внутренние символы названия заголовка должны совпадать. Отсутствующий обязательный заголовок блокирует весь пакет. Повтор одного обязательного заголовка блокирует пакет как неоднозначный.

Все дополнительные колонки, включая `Заявка`, `Тип заявки НО`, `Район`, `Исполнитель` и другие поля исходной системы, игнорируются и не сохраняются. Их наличие не считается ошибкой.

### 6.3. Форматы даты и времени

`Начало` и `Окончание` должны содержать дату и время. Принимаются следующие текстовые представления:

- `DD.MM.YYYY H:MM`;
- `DD.MM.YYYY HH:MM`;
- те же варианты с секундами `:SS`;
- `YYYY-MM-DD H:MM` или `YYYY-MM-DD HH:MM`, с необязательными секундами.

Секунды допустимы только для совместимости и отбрасываются после проверки. Значение без даты либо без времени является ошибкой. Неоднозначные локальные форматы с двузначным годом не принимаются.

Значения интерпретируются в часовом поясе проекта. CSV не должен содержать отдельное смещение UTC; если оно передано, строка получает ошибку формата.

### 6.4. Отображение полей заявки

| Источник | Поле заявки | Правило |
| --- | --- | --- |
| Дата из `Начало` | `sla_date` | Крайняя календарная дата выполнения |
| Дата из `Окончание` | контроль `sla_date` | Должна совпадать с датой из `Начало` |
| Время из `Начало` | `time_window_start` | Начало допустимого окна старта работы |
| Время из `Окончание` | `time_window_end` | Конец допустимого окна старта работы |
| `Тип заявки ВК` | `work_type_id` | Существующий активный тип работ проекта |
| `Адрес` | `address`, `latitude`, `longitude` | Канонический адрес и скрытые координаты адресного сервиса |
| Нет в CSV | `service_duration_min` | Копируется из выбранного типа работ при создании |
| Выбранный тип работ | эффективный приоритет | `CRITICAL`, `HIGH`, `MEDIUM` или `LOW`; отдельного поля приоритета у заявки нет |
| Нет в CSV | `status` | Всегда `NEW` |
| Нет в CSV | внутренний ID | Генерируется сервером |

Временное окно сохраняет действующую семантику заявки: начало работы должно попасть в интервал от `time_window_start` до `time_window_end`. Окончание самой работы может быть позже `time_window_end`, если соблюдены смена инженера и остальные ограничения solver.

## 7. Проверка файла

### 7.1. Последовательность

Проверка выполняется в фоне в следующем порядке:

1. проверить права, проект, расширение и размер;
2. вычислить SHA-256 исходного файла;
3. проверить повтор идентичного файла в проекте;
4. определить кодировку и разделитель;
5. разобрать заголовки;
6. определить информационные строки и лимит;
7. разобрать даты и время;
8. сопоставить типы работ;
9. нормализовать и геокодировать адреса;
10. проверить дубли внутри файла;
11. найти возможные дубли среди существующих заявок;
12. сохранить результат каждой строки и итог пакета.

Проверка не создаёт заявки и не запускает планирование.

### 7.2. Даты и окно

Для каждой строки обязательны оба значения. Дата из `Начало` должна совпадать с датой из `Окончание`. Разные строки файла могут иметь разные даты. `time_window_end` должен быть строго позже `time_window_start`.

Прошедшая дата разрешена: после применения такая заявка считается просроченной и участвует в планировании по действующим правилам SLA. Переход окна через полночь запрещён.

### 7.3. Тип работ

Название берётся из `Тип заявки ВК`. Перед поиском удаляются крайние пробелы, регистр не учитывается. Внутренние пробелы и остальные символы не исправляются автоматически.

Система ищет запись только среди типов работ текущего проекта:

- одно совпадение и `active = true` — значение корректно;
- совпадений нет — `UNKNOWN_WORK_TYPE`;
- найдено несколько совпадений после нормализации — `AMBIGUOUS_WORK_TYPE`;
- единственное совпадение неактивно — `INACTIVE_WORK_TYPE`.

Неизвестный тип не создаётся автоматически. Перед применением система повторно проверяет активность и принадлежность сохранённого `work_type_id`. Если справочник изменился после проверки, пакет переводится в состояние `STALE_VALIDATION` и должен пройти проверку заново.

### 7.4. Адрес

Адрес проверяется тем же сервисом и по тем же правилам, что ручное создание заявки. Требования:

- страна — Россия;
- присутствуют населённый пункт, улица и дом;
- найден один однозначный адрес;
- адресный сервис вернул координаты;
- координаты лежат в допустимых диапазонах.

В заявке сохраняются каноническая строка адреса, широта, долгота, идентификатор или стабильный ключ результата адресного сервиса, если он доступен. Исходный текст сохраняется только в строке аудита пакета и не подменяет канонический адрес.

Неполный, не найденный, нероссийский или неоднозначный адрес является ошибкой строки. Если адресный сервис недоступен, это техническая ошибка пакета, а не тысяча ошибок адресов. Заявки не создаются; пользователю доступен повтор проверки.

### 7.5. Пустые значения

Пустое значение в любой из четырёх обязательных колонок является ошибкой строки. Строка из одних пробелов считается пустой. Полностью пустые строки не учитываются в лимите и не отображаются как ошибки.

### 7.6. Дубли внутри файла

После нормализации строка идентифицируется составным ключом:

```text
canonical_address_key
+ sla_date
+ time_window_start
+ time_window_end
+ work_type_id
```

Если одинаковый ключ встречается несколько раз в одном CSV, все строки этой группы получают ошибку `DUPLICATE_IN_FILE` с перечислением номеров совпавших строк. Пакет применить нельзя.

### 7.7. Повтор идентичного файла

Если в том же проекте уже существует успешно применённый пакет заявок с той же SHA-256, новая загрузка блокируется кодом `FILE_ALREADY_APPLIED` и ссылкой на прежний пакет. Принудительное повторное применение идентичного файла отсутствует.

Если идентичный файл ранее только проверялся и ещё не применялся, сервер возвращает существующий пакет вместо создания дубля. Если прежняя проверка устарела из-за изменения справочников либо адресного провайдера, пользователь может запустить повторную проверку этого пакета.

### 7.8. Возможные дубли в базе

Система ищет в том же проекте существующие незакрытые заявки с совпадающим составным ключом. Совпадение создаёт предупреждение `POSSIBLE_EXISTING_DUPLICATE`, а не ошибку, поскольку одинаковые работы по одному адресу могут быть самостоятельными заявками.

Для применения пакета с такими предупреждениями пользователь устанавливает флажок «Я проверил возможные дубли и подтверждаю создание новых заявок». Подтверждение сохраняется с автором и временем. Отменённые заявки не формируют предупреждение.

## 8. Ошибки и предупреждения

### 8.1. Отображение

Ошибки и предупреждения показываются только на странице пакета. Скачивание CSV, XLSX или другого отчёта отсутствует.

Таблица содержит:

- номер строки исходного CSV, начиная с 1 для строки заголовков;
- уровень: ошибка или предупреждение;
- название колонки либо «Файл»;
- исходное значение, безопасно экранированное для HTML;
- код;
- понятное описание и действие пользователя.

Таблица поддерживает пагинацию, фильтр по уровню и поиск по номеру строки или коду. По умолчанию сначала показываются ошибки по возрастанию номера строки, затем предупреждения. Для ошибки уровня файла номер строки отображается как «—».

### 8.2. Минимальный набор кодов

| Код | Уровень | Условие |
| --- | --- | --- |
| `INVALID_FILE_TYPE` | Ошибка | Загружен не CSV |
| `FILE_TOO_LARGE` | Ошибка | Размер больше 10 МБ |
| `FILE_ALREADY_APPLIED` | Ошибка | Идентичный файл уже применён в проекте |
| `UNSUPPORTED_ENCODING` | Ошибка | Не удалось прочитать UTF-8 или Windows-1251 |
| `UNDETERMINED_DELIMITER` | Ошибка | Нельзя однозначно выбрать `;` или `,` |
| `MALFORMED_CSV` | Ошибка | Нарушены кавычки, число полей или структура CSV |
| `MISSING_HEADER` | Ошибка | Нет обязательной колонки |
| `DUPLICATE_HEADER` | Ошибка | Обязательный заголовок повторён |
| `ROW_LIMIT_EXCEEDED` | Ошибка | Более 1000 информационных строк |
| `REQUIRED_VALUE_MISSING` | Ошибка | Пустая обязательная ячейка |
| `INVALID_DATETIME` | Ошибка | Дата или время не распознаны |
| `DATE_MISMATCH` | Ошибка | Даты начала и окончания различаются |
| `INVALID_TIME_WINDOW` | Ошибка | Окончание не позже начала |
| `UNKNOWN_WORK_TYPE` | Ошибка | Тип работ не найден |
| `AMBIGUOUS_WORK_TYPE` | Ошибка | Найдено несколько типов работ |
| `INACTIVE_WORK_TYPE` | Ошибка | Тип работ неактивен |
| `ADDRESS_NOT_FOUND` | Ошибка | Адрес не найден |
| `ADDRESS_INCOMPLETE` | Ошибка | Нет города, улицы или дома |
| `ADDRESS_AMBIGUOUS` | Ошибка | Найдено несколько адресов без однозначного выбора |
| `ADDRESS_OUTSIDE_RUSSIA` | Ошибка | Адрес не относится к России |
| `ADDRESS_SERVICE_UNAVAILABLE` | Ошибка пакета | Адресный сервис недоступен |
| `DUPLICATE_IN_FILE` | Ошибка | Строки имеют одинаковый составной ключ |
| `POSSIBLE_EXISTING_DUPLICATE` | Предупреждение | Похожая незакрытая заявка уже есть в проекте |
| `STALE_VALIDATION` | Ошибка пакета | Данные изменились между проверкой и применением |

Тексты интерфейса не должны раскрывать стек, SQL, ключи провайдера или другие технические детали.

## 9. Пользовательский сценарий

### 9.1. Страница импортов

Для заявок интерфейс предлагает загрузить CSV и показывает требования:

- обязательные колонки;
- поддерживаемые кодировки и разделители;
- допустимые форматы даты и времени;
- ограничение 1000 строк и 10 МБ;
- правило одинаковой даты внутри каждой строки;
- правило «при любой ошибке ничего не создаётся».

Импорт инженеров через XLSX остаётся отдельным существующим действием. Старые XLSX-пакеты заявок доступны только для просмотра истории; применить заново или загрузить новый XLSX с заявками нельзя.

### 9.2. Загрузка и проверка

После выбора файла пользователь нажимает «Проверить файл». Сервер создаёт пакет и возвращает страницу состояния. Проверка выполняется асинхронно; страницу можно закрыть. При повторном открытии состояние загружается с сервера.

Во время проверки показываются:

- имя файла;
- проект;
- автор;
- время загрузки;
- текущий этап;
- обработанное и общее количество строк, если оно известно.

### 9.3. Результат с ошибками

Если найдена хотя бы одна ошибка:

- статус пакета — «Есть ошибки»;
- показываются количество строк, ошибок и предупреждений;
- кнопка «Создать заявки» недоступна;
- ошибки выводятся в экранной таблице;
- текст поясняет, что исходный CSV нужно исправить и загрузить заново;
- скачать отчёт нельзя и не требуется.

### 9.4. Результат без ошибок

Если ошибок нет, экран показывает:

- количество заявок к созданию;
- диапазон крайних дат;
- количество уникальных типов работ;
- количество нормализованных адресов;
- количество предупреждений о возможных дублях;
- кнопку «Создать заявки».

При наличии предупреждений кнопка становится доступной только после подтверждения проверки дублей. Если предупреждений нет, дополнительный флажок не показывается.

### 9.5. Применение

После нажатия «Создать заявки» пакет получает состояние «Создаётся». Повторное нажатие блокируется. При успехе экран показывает:

- «Импорт завершён»;
- количество созданных заявок;
- дату и время завершения;
- ссылку «Открыть заявки» с фильтром по этому пакету;
- состояние события динамического пересчёта или ссылку на актуальный расчёт, если такая связь уже поддерживается интерфейсом.

### 9.6. История

История импортов содержит:

- имя файла;
- тип данных «Заявки CSV» либо исторический тип;
- проект;
- автора;
- дату загрузки;
- статус;
- количество строк, ошибок, предупреждений и созданных заявок;
- действие «Открыть».

История и сохранённые ошибки остаются после удаления исходного файла по сроку хранения.

## 10. Состояния пакета

| Состояние | Значение | Доступное действие |
| --- | --- | --- |
| `UPLOADED` | Файл сохранён, проверка ещё не началась | Ожидать |
| `VALIDATING` | Идёт фоновая проверка | Открывать состояние, покинуть страницу |
| `HAS_ERRORS` | Найдены блокирующие ошибки | Исправить и загрузить новый файл |
| `READY_TO_APPLY` | Ошибок нет | Подтвердить предупреждения и создать заявки |
| `APPLYING` | Выполняется транзакция создания | Ожидать |
| `APPLIED` | Все заявки созданы | Открыть созданные заявки |
| `TECHNICAL_ERROR` | Проверка или применение не завершились по технической причине | Повторить безопасную операцию |
| `STALE_VALIDATION` | Справочники или проверяемые данные изменились | Повторить проверку |
| `EXPIRED` | Исходный файл удалён до применения после срока хранения | Загрузить файл заново |

Переход из `APPLIED` в другое состояние запрещён. `HAS_ERRORS` не переводится в `READY_TO_APPLY` редактированием строк на сервере: пользователь загружает исправленный файл.

## 11. Применение и создание заявок

### 11.1. Предварительная повторная проверка

Перед началом транзакции backend проверяет:

- пакет принадлежит проекту и ещё не применён;
- статус `READY_TO_APPLY`;
- контрольная сумма и сохранённый нормализованный payload не изменились;
- пользователь имеет право на проект;
- проект активен;
- все выбранные типы работ существуют, активны и принадлежат проекту;
- версия правил адресной нормализации и сохранённые результаты допустимы;
- подтверждение предупреждений присутствует, если оно необходимо.

При несоответствии заявки не создаются.

### 11.2. Транзакция

В одной транзакции система:

1. блокирует пакет от параллельного применения;
2. повторно убеждается, что нет применённого пакета с тем же хешем;
3. создаёт по одной заявке для каждой строки;
4. копирует `service_duration_min` из актуального типа работ;
5. назначает `status = NEW`; эффективный приоритет определяет связанный тип работ;
6. сохраняет связь каждой заявки со строкой и пакетом импорта;
7. записывает аудит;
8. создаёт одно outbox-событие массового добавления заявок;
9. переводит пакет в `APPLIED` и фиксирует счётчики.

Если любая операция завершается ошибкой, транзакция откатывается целиком. Пакет получает безопасное состояние для повторной попытки либо `STALE_VALIDATION`; частично созданных заявок быть не должно.

### 11.3. Идемпотентность

Повтор одного запроса применения с тем же ключом идемпотентности возвращает уже полученный результат. Параллельные запросы не создают дубли. Серверная блокировка и ограничение базы данных должны гарантировать однократное применение пакета.

## 12. Связь с динамическим планированием

После фиксации транзакции worker публикует одно событие:

```text
event_type = JOBS_IMPORTED
project_id
import_batch_id
job_ids[]
created_at
```

Событие обрабатывается по правилам ТЗ динамического добавления заявок:

- все заявки одного пакета рассматриваются одной пачкой;
- событие может объединиться с другими близкими событиями того же проекта в согласованном окне debounce;
- заявки с `sla_date <= D0` участвуют в сегодняшней ветке;
- заявки с `sla_date > D0` не меняют текущий день и начинают участвовать с будущих дат;
- смешанный пакет разделяется алгоритмом по каждой заявке, но не создаёт отдельный запуск на строку;
- неуспех solver не откатывает уже созданные заявки;
- состояние расчёта и причины неназначения отображаются существующими средствами планирования.

Если публикация outbox-события временно не удалась, worker повторяет доставку. Одна заявка не должна попасть в план дважды из-за повторной доставки события.

## 13. Данные и хранение

### 13.1. Пакет импорта

Существующая модель пакета расширяется либо заменяется эквивалентной структурой:

```text
import_batch
  id
  project_id
  entity_type = JOBS_CSV
  original_filename
  content_sha256
  source_encoding
  source_delimiter
  status
  validation_rules_version
  address_provider_version
  total_rows
  error_count
  warning_count
  created_count
  warnings_acknowledged_by
  warnings_acknowledged_at
  created_by
  created_at
  validation_started_at
  validation_finished_at
  applied_at
  source_file_expires_at
  technical_error_category
```

### 13.2. Результат строки

Для пагинации и аудита результат каждой информационной строки хранится отдельно:

```text
import_batch_row
  id
  batch_id
  row_number
  raw_required_values_json
  normalized_address
  canonical_address_key
  latitude
  longitude
  sla_date
  time_window_start
  time_window_end
  work_type_id
  severity
  issues_json
  created_job_id
```

`raw_required_values_json` содержит только четыре используемых исходных значения. Остальные колонки файла в базу не копируются. Значения, показанные в интерфейсе, экранируются.

### 13.3. Связь заявки с импортом

Созданная заявка хранит `import_batch_id` и `import_row_number` либо эквивалентную неизменяемую связь в таблице происхождения. Эти поля не показываются инженеру и не являются внешним ID заявки.

### 13.4. Срок хранения

- исходный CSV хранится 30 календарных дней с момента загрузки;
- после истечения срока фоновая задача удаляет файл, но сохраняет SHA-256, метаданные, результаты строк, ошибки, предупреждения, созданные ID и аудит;
- применённые заявки не зависят от наличия исходного файла;
- неприменённый пакет без исходного файла получает `EXPIRED`.

## 14. API

Названия маршрутов могут быть адаптированы к соглашениям проекта, но контракт должен обеспечивать следующее поведение.

### 14.1. Создать пакет

```text
POST /api/projects/{project_id}/job-imports
Content-Type: multipart/form-data
file: <csv>
```

Успех: `202 Accepted` с `batch_id`, состоянием `UPLOADED` или `VALIDATING` и ссылкой состояния. Передача XLSX или Numbers возвращает `415 INVALID_FILE_TYPE`. Файл больше 10 МБ возвращает `413 FILE_TOO_LARGE`.

### 14.2. Получить пакет

```text
GET /api/projects/{project_id}/job-imports/{batch_id}
```

Ответ содержит метаданные, состояние, прогресс, счётчики, итоговую сводку и признак необходимости подтверждения предупреждений.

### 14.3. Получить проблемы строк

```text
GET /api/projects/{project_id}/job-imports/{batch_id}/issues
    ?severity=ERROR|WARNING
    &query=
    &page=
```

Ответ содержит пагинированные данные для экранной таблицы. API для скачивания отчёта отсутствует.

### 14.4. Повторить проверку

```text
POST /api/projects/{project_id}/job-imports/{batch_id}/revalidate
```

Доступно после исправимой технической ошибки или `STALE_VALIDATION`, пока исходный файл не удалён. Повтор не создаёт новый пакет.

### 14.5. Применить пакет

```text
POST /api/projects/{project_id}/job-imports/{batch_id}/apply
Idempotency-Key: <uuid>
{
  "acknowledge_warnings": true | false
}
```

Успех возвращает `202 Accepted` либо `200 OK` в зависимости от способа выполнения, идентификатор операции и затем итог `created_count` и `planning_event_id`.

Основные конфликты:

- `409 IMPORT_ALREADY_APPLIED`;
- `409 WARNINGS_NOT_ACKNOWLEDGED`;
- `409 STALE_VALIDATION`;
- `409 FILE_ALREADY_APPLIED`;
- `422 IMPORT_HAS_ERRORS`.

## 15. Фоновая обработка и устойчивость

- очередь проверок разделяется по проекту и не допускает неограниченного параллелизма адресных запросов;
- применяется контролируемая пакетная отправка адресов с учётом лимитов провайдера;
- временные ошибки адресного сервиса повторяются с ограниченным backoff;
- после исчерпания попыток пакет получает `TECHNICAL_ERROR` и понятное действие «Повторить проверку»;
- worker периодически восстанавливает зависшие `VALIDATING` и `APPLYING` по lease или heartbeat;
- закрытие вкладки не отменяет серверную задачу;
- повтор задачи не создаёт новый пакет и не дублирует результат;
- удаление исходного файла выполняется отдельной идемпотентной задачей хранения.

## 16. Аудит, журналирование и метрики

### 16.1. Аудит

Минимальные события:

- `JOB_IMPORT_UPLOADED`;
- `JOB_IMPORT_VALIDATION_STARTED`;
- `JOB_IMPORT_VALIDATED`;
- `JOB_IMPORT_HAS_ERRORS`;
- `JOB_IMPORT_WARNINGS_ACKNOWLEDGED`;
- `JOB_IMPORT_APPLY_STARTED`;
- `JOB_IMPORT_APPLIED`;
- `JOB_IMPORT_TECHNICAL_ERROR`;
- `JOB_IMPORT_SOURCE_DELETED`;
- `PLANNING_EVENT_CREATED_FROM_IMPORT`.

Аудит хранит проект, пакет, автора, время, контрольную сумму, счётчики и безопасную категорию ошибки. Пароли, ключи адресного сервиса и полный файл в метаданные журнала не записываются.

### 16.2. Технические журналы

Логируются:

- `batch_id`, `project_id`, фаза и длительность;
- выбранные кодировка и разделитель;
- количество строк, ошибок, предупреждений и созданных заявок;
- число адресных запросов, повторов и cache hit;
- переходы состояний;
- идентификатор транзакции применения и outbox-события;
- безопасная категория исключения.

### 16.3. Метрики

- число загрузок и применений;
- доля пакетов с ошибками;
- p50, p95 и p99 времени проверки;
- p50, p95 и p99 времени применения;
- ошибки по кодам;
- доля адресов, не прошедших нормализацию;
- число предупреждений о дублях и доля подтверждённых;
- число блокировок повторного файла;
- число созданных заявок;
- задержка от `APPLIED` до создания события планирования;
- число зависших и повторно обработанных фоновых задач.

## 17. Безопасность

- MIME и расширение проверяются, но MIME не считается достаточным доказательством формата;
- размер ограничивается до сохранения полного тела, если это поддерживает инфраструктура;
- имя файла очищается и не используется как путь;
- CSV обрабатывается как данные, формулы не выполняются;
- все значения при выводе экранируются от HTML и script injection;
- исходный файл хранится вне публичной директории;
- ссылка на файл, если используется внутри системы, доступна только авторизованным пользователям проекта;
- удаление исходного файла по сроку хранения подтверждается аудитом;
- API применяет CSRF либо токенную защиту согласно типу клиента;
- rate limit ограничивает массовые загрузки одного пользователя и проекта.

## 18. Пограничные случаи

- CSV содержит запятую в адресе при разделителе `,`: значение обязано быть заключено в кавычки и корректно разбирается CSV-парсером.
- В начале файла присутствует BOM: он удаляется только из первого заголовка.
- Есть полностью пустые строки между данными: они игнорируются, номера последующих строк сохраняются исходными.
- В строке больше колонок, чем в заголовке: `MALFORMED_CSV`.
- Один заголовок повторён: `DUPLICATE_HEADER`.
- В разных строках разные даты: это разрешено.
- В одной строке начало 17.09, окончание 18.09: `DATE_MISMATCH`, весь пакет заблокирован.
- Начало равно окончанию: `INVALID_TIME_WINDOW`.
- Дата прошла: заявка создаётся и считается просроченной.
- Тип работ переименовали или архивировали после проверки: `STALE_VALIDATION`, повторная проверка.
- Адресный сервис вернул несколько домов: `ADDRESS_AMBIGUOUS`.
- Адресный сервис недоступен: одна техническая ошибка пакета, заявки не создаются.
- Два пользователя одновременно применяют один пакет: заявки создаются один раз.
- Клиент повторил запрос после таймаута: идемпотентный ответ без дублей.
- Solver завершился ошибкой после импорта: заявки остаются созданными и видимыми, событие планирования повторяется по своим правилам.
- Файл удалён по сроку хранения до применения: пакет `EXPIRED`, требуется новая загрузка.
- В файле ноль информационных строк: ошибка `NO_DATA_ROWS`.

## 19. Тест-кейсы

### 19.1. Файл и парсер

1. UTF-8 CSV с `;` успешно определяется.
2. UTF-8 с BOM и разделителем `,` успешно определяется.
3. Windows-1251 CSV успешно читается.
4. Адрес с запятой в кавычках не разбивается на колонки.
5. Неэкранированная кавычка формирует `MALFORMED_CSV`.
6. XLSX и Numbers отклоняются.
7. Файл больше 10 МБ отклоняется.
8. 1000 строк принимаются, 1001 строка блокирует пакет.
9. Пустые строки не учитываются в лимите.
10. Дополнительные колонки игнорируются.

### 19.2. Строки

1. Все четыре обязательных значения корректно преобразуются.
2. Каждый обязательный столбец проверяется на пустое значение.
3. Поддерживаются согласованные форматы даты и времени.
4. Одинаковые даты начала и окончания сохраняются как один SLA.
5. Разные даты одной строки блокируют пакет.
6. Разные даты разных строк разрешены.
7. Окончание не позже начала блокирует пакет.
8. Прошедшая дата разрешена.
9. Тип работ находится без учёта регистра и крайних пробелов.
10. Неизвестный, неоднозначный и неактивный типы дают разные коды.
11. Адрес сохраняется в каноническом виде с координатами.
12. Неполный, неоднозначный и нероссийский адрес дают разные коды.
13. Значение `Заявка` не сохраняется как внешний ID.
14. Длительность копируется из типа работ.
15. Статус равен `NEW`, эффективный приоритет совпадает с приоритетом выбранного типа работ.

### 19.3. Дубли

1. Две одинаковые строки внутри файла блокируют пакет и показывают обе строки.
2. Возможный дубль в базе создаёт предупреждение.
3. Без подтверждения предупреждения применить пакет нельзя.
4. После подтверждения обе самостоятельные заявки могут существовать.
5. Повтор идентичного применённого файла блокируется.
6. Идентичная повторная загрузка неприменённого файла открывает прежний пакет.

### 19.4. Транзакция и планирование

1. При ошибке одной строки не создаётся ни одной заявки.
2. Ошибка на середине применения откатывает все созданные записи и outbox.
3. Успешное применение создаёт ровно столько заявок, сколько информационных строк.
4. Повтор применения не создаёт дубли.
5. Один пакет создаёт одно событие `JOBS_IMPORTED`.
6. Смешанный набор SLA передаётся одним событием и классифицируется алгоритмом планирования.
7. Ошибка solver не откатывает заявки.

### 19.5. Права и интерфейс

1. Диспетчер работает только в своём проекте.
2. Владелец обязан выбрать проект.
3. Инженер получает отказ для страниц и API.
4. Заблокированный проект не принимает импорт.
5. Ошибки видны на экране с пагинацией и фильтрами.
6. Ссылки на скачивание отчёта отсутствуют.
7. Страницу можно закрыть и открыть без потери прогресса.
8. История показывает старые XLSX-пакеты и новые CSV-пакеты.
9. После применения доступна ссылка на созданные заявки.

## 20. Критерии приёмки

1. Для заявок интерфейс принимает только `.csv`; новый XLSX или Numbers загрузить нельзя.
2. Импорт инженеров через XLSX работает как прежде.
3. Поддерживаются UTF-8, UTF-8 с BOM и Windows-1251, разделители `;` и `,`.
4. Обязательные заголовки: `Тип заявки ВК`, `Начало`, `Окончание`, `Адрес`; порядок произвольный, дополнительные колонки игнорируются.
5. Из `Начало` формируются `sla_date` и `time_window_start`, из `Окончание` проверяется та же дата и формируется `time_window_end`.
6. Разные даты одной строки блокируют весь пакет; разные даты разных строк разрешены.
7. `Тип заявки ВК` сопоставляется с единственным активным типом работ текущего проекта без учёта регистра и крайних пробелов.
8. Адрес проходит тот же российский поиск до дома, что ручная форма, и сохраняется с координатами.
9. Прошедший SLA разрешён.
10. Импортированная заявка получает серверный внутренний ID, `NEW`, длительность и эффективный приоритет из типа работ.
11. Колонка `Заявка` и прочие внешние идентификаторы не сохраняются.
12. Максимум — 1000 информационных строк и 10 МБ.
13. Полностью пустые строки игнорируются, частично заполненные проверяются как ошибки.
14. Любая ошибка блокирует создание всех заявок.
15. Ошибки и предупреждения показываются только на экране; файл отчёта не создаётся.
16. Полные дубли внутри файла являются ошибкой.
17. Возможные дубли в базе являются предупреждением и требуют подтверждения.
18. Повтор идентичного применённого файла блокируется по SHA-256 в пределах проекта.
19. Проверка выполняется в фоне и не зависит от открытой вкладки.
20. После успешной проверки пользователь отдельно нажимает «Создать заявки».
21. Применение атомарно и идемпотентно.
22. Успешный пакет создаёт одно событие динамического пересчёта для всех новых заявок.
23. Ошибка solver не отменяет созданные заявки.
24. История хранит автора, проект, файл, статус, счётчики и проблемы строк.
25. Исходный CSV удаляется через 30 дней, а метаданные, хеш, ошибки и связи с заявками сохраняются.
26. Владелец и диспетчер имеют согласованный доступ, инженер не имеет доступа.
27. Данные проектов изолированы на уровне интерфейса, API, фоновых задач и базы.

## 21. План внедрения

1. Добавить состояния и поля пакета, таблицу результатов строк и связь происхождения заявки.
2. Добавить хранение файла, SHA-256 и политику удаления через 30 дней.
3. Реализовать безопасный CSV-парсер и определение кодировки и разделителя.
4. Реализовать фоновую валидацию и интеграцию адресного сервиса.
5. Добавить экранные ошибки, предупреждения, подтверждение дублей и историю.
6. Реализовать атомарное и идемпотентное применение.
7. Добавить transactional outbox и событие `JOBS_IMPORTED`.
8. Подключить событие к действующей очереди динамического пересчёта.
9. Переключить импорт заявок с XLSX на CSV, не меняя импорт инженеров.
10. Выполнить миграцию старых пакетов для чтения истории.
11. Включить функцию сначала на тестовом проекте через feature flag.
12. Проверить метрики, затем включить для всех проектов.

Откат интерфейса не должен удалять уже созданные заявки или старые пакеты. Миграции должны позволять старому коду читать существующие данные на период поэтапного включения.

## 22. Риски и меры

| Риск | Последствие | Мера |
| --- | --- | --- |
| CSV неоднозначно разобран | Значения попадают не в те поля | Ограниченный набор кодировок и разделителей, проверка заголовков и полноценный parser |
| Адресный сервис медленный или недоступен | Долгая проверка или массовые ложные ошибки | Фоновая обработка, rate limit, cache, retry и отдельная техническая ошибка пакета |
| Справочник изменился после проверки | Создана заявка с неактуальным типом | Повторная проверка ссылок и `STALE_VALIDATION` |
| Пользователь дважды применил пакет | Дубли заявок | SHA-256, idempotency key, блокировка строки и ограничение базы |
| Совпадающие заявки на самом деле самостоятельны | Ложная блокировка бизнеса | Совпадение с базой является подтверждаемым предупреждением |
| Большое число проблем перегружает страницу | Интерфейс становится медленным | Отдельная таблица строк, серверная пагинация и фильтры |
| Событие планирования потеряно после commit | Новые заявки не попадают в автоматический расчёт | Transactional outbox и повторная доставка |
| Повтор доставки события | Повторное назначение или лишний расчёт | Идемпотентный consumer по event ID и batch ID |
| Исходный файл хранится дольше необходимого | Лишний объём и риск доступа | Автоматическое удаление через 30 дней и аудит удаления |
