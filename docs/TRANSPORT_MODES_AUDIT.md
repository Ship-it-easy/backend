# Проверка режимов передвижения (26 сентября 2026)

## Причина таймаута

`PUBLIC_TRANSPORT` использовал датированный Valhalla `multimodal`. В отличие от
автомобиля, пешехода и велосипеда, для этого профиля планировщик запрашивал
маршрут каждой пары точек через `/route`, а затем повторно проверял выбранные
переезды после изменения расписания. На недельном пакете это приводило к сотням
дорогих запросов и завершению по таймауту. Режим, MosMetro, GTFS-скрипты и
конфигурация удалены. Остальные три профиля используют матричный API
`/sources_to_targets`.
Построение временных зон Valhalla сохранено: автомобильный API карты отправляет
датированные дорожные запросы, которым нужны локальные временные зоны.

## Контрольный прогон

Прогон выполнен на сохранённом пакете №58 (74 заявки, 6 инженеров). Скрипт
`scripts/benchmark_road_week.py` подменял тип всех инженеров **только в памяти**,
не публиковал план и сохранял лишь обычный дорожный кэш. Лимит — 600 секунд.

| Профиль | Доступно по требованиям транспорта | Назначено | Время |
| --- | ---: | ---: | ---: |
| Автомобиль | 74 | 73 | 93,8 с |
| Пешеход | 51 | 50 | 20,7 с |
| Велосипед | 51 | 50 | 67,6 с |

23 заявки требуют именно `CAR`, поэтому они недоступны велосипедистам и
пешеходам. Велосипедный профиль не демонстрирует проблемы производительности;
его стоит сохранить.

Отдельно проверен живой расчёт карты через локальную Valhalla: для одной пары
московских адресов получены маршруты `auto`, `pedestrian` и `bicycle`.
Холодная матрица тех же 80 точек, без чтения или записи дорожного кэша БД,
построилась за 11,8 с для `auto` и за 22,2 с для `bicycle`. В каждом случае
158 из 6400 направленных ячеек остались недоступными.

В обоих прогонах осталась заявка №161. Она находится в точке 56.759039,
37.124469; локальная Valhalla возвращает HTTP 400, код 171, для маршрута от
стартовой точки инженера в режимах `auto`, `bicycle` и `pedestrian`. Это отдельная
проблема достижимости адреса или покрытия дорожного графа. Удалять заявку либо
ослаблять требование `CAR` ради успешного статуса пакета нельзя.

## Переход существующих данных

В снимке пакета №58 у всех шести инженеров записано `PUBLIC_TRANSPORT`.
В действующей локальной БД таких инженеров восемь: один в проекте №1, шесть
в проекте №11 и один в проекте №12. Типов работ с прежним требованием нет.
Миграция `a4d6f2b91c70` перевела таких инженеров и старые требования типов работ
в пешеходный `NONE`. Старые снимки планирования также читаются как пешие.
Ограничения БД запрещают новые значения транспорта вне `CAR`, `NONE` и `BICYCLE`.
Миграция создала по одному системному событию полного перерасчёта для каждого
затронутого проекта; backend обработал их при запуске.
Полный `upgrade` и `downgrade` проверены на временных таблицах PostgreSQL с
откатом транзакции; рабочие таблицы при проверке не изменялись.
Владение автомобилем нельзя вывести из прежнего режима; для 23 автомобильных
заявок нужно назначить `CAR` инженерам, у которых действительно есть машина.

## Проверка после развёртывания

Локальный Docker-стек пересобран 26 сентября 2026 года. Backend запустился с
ревизией БД `a4d6f2b91c70`, MosMetro-контейнер удалён, а `/openapi.json`
отвечает HTTP 200. Публичная схема принимает только `CAR`, `NONE` и `BICYCLE`.
В БД больше нет инженеров или типов работ с `PUBLIC_TRANSPORT`; ограничения
новых значений транспорта применены.

| Проект | Новая текущая версия плана | Назначено | Не назначено | Время перерасчёта |
| --- | ---: | ---: | ---: | ---: |
| №1 | 17 | 8 | 0 | 25 с |
| №11 | 4 | 50 | 24 | 23 с |
| №12 | 4 | 8 | 0 | 32 с |

Все три системных события получили состояние `PUBLISHED`, без ошибок дней.
В проекте №11 все шесть инженеров теперь пешие. Из 24 неназначенных заявок
23 требуют `CAR` и имеют диагноз `NO_COMPATIBLE_ENGINEER_IN_HORIZON`; заявка
№161 имеет диагноз `NOT_ASSIGNED_WITHIN_HORIZON`. Для неё отдельно нужно
проверить геокодирование и покрытие дорожного графа Valhalla. Замеры выполнены
локально на одном пакете, поэтому сами по себе не гарантируют время для всех
районов.

Преддемонстрационное ревью показало, что FIFO-сравнение проекта №11 не готово
для показа: 28 из 30 дневных сравнений завершились
`BASELINE_DISTANCE_DATA_NOT_READY`. FIFO пытается провести пешего инженера по
недоступной дорожной дуге, в том числе к заявке №161. Это не отменяет
опубликованные оптимальные планы. Фоновая гонка при исчерпании попыток повтора
вызывала необработанные исключения в логах; обработка терминального состояния
исправлена отдельно. Для показа корректного FIFO-сравнения сохранён проект №8:
read-only smoke на текущем backend `8000` подтвердил план версии 14, 8/8
назначений и `READY` на 27 сентября.

В проектах №1 и №12 старые опубликованные версии со снимками
`PUBLIC_TRANSPORT` остались в истории. Их заменили новые текущие версии,
опубликованные системными событиями миграции.
